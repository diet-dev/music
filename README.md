# Music

Музыкальный плеер на Web Audio для браузерных игр: зацикленные треки с кроссфейдом, приглушением и управлением темпом.

## Установка

```bash
npm install @dietdev/music
```

```ts
import { MusicPlayer } from "@dietdev/music";
```

Пакет публикуется собранным: `dist/` содержит ES-модули и декларации типов. Для потребителя нужен Node.js 18+ и, если проект на TypeScript, компилятор 5.7 или новее — декларации сохраняют расширения `.ts` в относительных импортах, а разрешать их научились начиная с этой версии.

## Зачем

Фоновая музыка в игре — это не «включить `<audio loop>`». Нужны:

- **кроссфейд** между треками (меню → бой → босс → меню) без щелчков и пауз;
- **приглушение** (даккинг) на паузе и в модалках — с «подводным» lowpass, а не просто тише;
- **несколько независимых причин молчать**: выключено в настройках, идёт реклама, вкладка скрыта. Сводить их к одному флагу нельзя — иначе возврат из рекламы включит музыку тому, кто выключил её в настройках;
- **экономия трафика**: пока музыка выключена настройкой — треки вообще не качаются;
- **слоу-мо**: темп `playbackRate` вниз, lowpass вслед за ним — «звук уходит» вместе со временем;
- **автоплей-политики**: `AudioContext` рождается suspended и законно ждёт пользовательского жеста.

Все константы подобраны на слух и переопределяются опциями — экспортируются как `musicDefaults`.

## Как это работает

Граф: `source → свой GainNode → lowpass (BiquadFilter) → master (GainNode) → destination`.

- Свой `GainNode` на каждый источник: затухающий трек не пересекается со следующим `play()`, даже если тот случился раньше реальной остановки. Слот отключается от графа по `source.onended`, а не в момент ухода в затухание.
- `master` держит громкость (опции × даккинг, ноль при любой причине молчания) — короткими рампами, чтобы не щёлкало.
- `lowpass` открыт в обычной игре, приопущен на паузе и следует за темпом слоу-мо.

## Использование

```ts
import { MusicPlayer } from "@dietdev/music";

const music = new MusicPlayer({
  tracks: {
    // Порядок ключей — приоритет загрузки в loadAll(): первый нужен раньше всех
    battle: "/assets/music/battle.mp3",
    menu: "/assets/music/menu.mp3",
    boss: "/assets/music/boss.mp3",
  },
  onError: (err) => reportError(err), // плеер никогда не бросает исключения
});

// Рано, откуда угодно — контекст родится suspended, это законно:
music.init();

// После первого пользовательского жеста (клик, тап, нажатие клавиши):
music.resume();

// Треки качаются последовательно в порядке объявления:
music.loadAll();

// Смена трека — кроссфейд; незагруженный трек включится по готовности:
music.play("battle");

// Пауза/модалка:
music.duck(true);

// Реклама / скрытая вкладка:
music.setSuspended("ad", true);
document.addEventListener("visibilitychange", () => {
  music.setSuspended("hidden", document.hidden);
});

// Тумблер в настройках. Включение само дотягивает треки и доигрывает желаемый:
music.setEnabled(!muted);

// Слоу-мо:
music.setRate(0.7);
```

## API

| Метод                               | Что делает                                                                                                     |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `init()`                            | Создаёт `AudioContext` и граф. Идемпотентен; жеста не требует                                                  |
| `resume()`                          | Будит suspended-контекст. Звать из обработчика жеста или когда все причины молчания сняты                      |
| `load(id)`                          | Качает и декодирует один трек; дедуплицируется; упавшая загрузка не кэшируется                                 |
| `loadAll()`                         | Грузит треки последовательно в порядке объявления. Ничего не тянет, пока `enabled === false` или нет контекста |
| `play(id)`                          | Кроссфейд к треку; запоминает желание до появления контекста/буфера                                            |
| `stop()`                            | Уводит текущий трек в затухание и забывает желание                                                             |
| `setEnabled(on)`                    | Тумблер настройки. `true` дотягивает треки и доигрывает желаемый                                               |
| `setSuspended(source, on)`          | Причина молчания: `"ad"` \| `"hidden"`. `"hidden"` дополнительно усыпляет контекст (батарея)                   |
| `duck(on)`                          | Приглушение с lowpass «под воду» (пауза, модалки)                                                              |
| `setRate(rate)`                     | Темп с рампой, включая затухающие источники; lowpass следует за темпом                                         |
| `debugVolume(v)`, `debugFilter(hz)` | Дев-хуки: мгновенно, мимо рамп — для подбора значений из консоли                                               |

Опции: `tracks` (обязательна), `volume` (0.35), `crossfade` (0.6 с), `duckLevel` (0.3), `duckHz` (400 Гц), `openHz` (20000 Гц), `ramp` (0.08 с), `slomoFilterHz` (2500 Гц), `minRate` (0.7), `onError`. Дефолты экспортируются как `musicDefaults`.

Чистая математика вынесена в `targetGain()` и `slomoFilterHz()` — проверяется тестами без Web Audio.

## Ограничения

- Только браузер: `AudioContext` в Node нет. Тесты проверяют чистую математику и логику гейтов (что грузится, а что нет) — граф слушается вручную в браузере.
- Декод через `fetch` + `decodeAudioData`: для стриминга больших треков ничего не сделано, все треки лежат в памяти как `AudioBuffer`.
- `setSuspended` принимает только `"ad" | "hidden"` — других причин у веб-игр не встречалось.
